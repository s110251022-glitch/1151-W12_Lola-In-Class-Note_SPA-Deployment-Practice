From Analysis to Product從分析到產品

BNA-EMI = Analysis — decompose a problem, represent it, build a product, and capture it with AI. BNA-EMI＝分析：拆解問題、重新呈現、打造產品，並用 AI 記錄與整理。

One-sentence summary一句話總結

BNA = Analysis: break a problem into parts (① Separate), study the parts and their relationships (② Investigate), rebuild them with evidence (③ Recombine), and present the result as a systematic, structured, process-oriented representation (e.g., a Coggle mind map) to generate insights and reach the goal effectively. The same logic is applied to the Term Project (TP) = a product (the BNA Agent), framed by PRD → MVP → value (WTP) → Market, and to AI-assisted note-taking that turns class notes into Markdown documents and web outputs.

BNA 的核心是分析：先把問題拆開（① Separate 拆解），研究各部分及彼此的關係（② Investigate 調查），再用證據重組（③ Recombine 重組），並以系統化、結構化、流程導向的方式呈現（例如 Coggle 心智圖），進而產生洞見、有效地達成目標。同一套邏輯也用在期末專題（Term Project, TP）＝一個產品（BNA Agent），依循 PRD → MVP → 價值（WTP）→ 市場的路徑；最後用 AI 輔助課堂筆記，把筆記轉成 Markdown 文件與網頁輸出。

Analysis: a 3-step process分析：三步驟流程

“BNA-EMI = Analysis” — the core method of the course「BNA-EMI＝分析」：本課程的核心方法

Process流程

①Separate拆解 Separate
Split the situation into:把情境拆成：
  • the problem問題（the problem）
  • the demand需求（the demand）
  • the questions提問（the questions）
➜
Decompose細分 Decompose
  • Σ Parts 各部分
  • Σ Components 各組成
  • ★ potential relationships潛在關係
★ = important重要
➜
②Investigate調查 Investigate
Examine each part, component and relationship in depth (applied to the TP).深入檢視每個部分、組成與關係（套用到期末專題 TP）。
➜
③Recombine重組 Recombine
Rebuild the whole with evidences: support each claim with “e.g. / for example”.以證據重建整體：每個主張都附上「例如（e.g. / for example）」。
Step步驟What you do要做什麼Output產出
① SeparateSplit into problem / demand / questions拆成問題、需求、提問A clear list of what is being asked and why清楚列出「被問什麼、為什麼」
DecomposeTurn them into Σ Parts and Σ Components; identify their potential relationships ★再細分成各部分與各組成，並找出彼此的潛在關係 ★Building blocks + how they may connect基本元件＋它們可能如何連結
② InvestigateExamine each part and relationship逐一研究每個部分與關係Facts and findings per part各部分的事實與發現
③ RecombinePut the parts back together, every claim backed by evidence把各部分組回整體，每個主張都有證據支持An evidence-backed whole (argument, model or product design)有證據支撐的整體（論述、模型或產品設計）

Why it works為什麼這樣做有效 inferred推論

  • Separate prevents answering the wrong question — first confirm problem vs. demand vs. question.
  • Σ (sum of) parts / components: the whole = the parts plus their relationships. The lecturer starred the relationships — analysing parts without relationships loses the system view.
  • Recombine with evidence makes the analysis verifiable: each statement comes with an example or data point (“e.g.”).
  • 先拆解可以避免答錯題：先分清楚「問題、需求、提問」各是什麼。
  • Σ（加總）各部分／各組成：整體＝各部分加上它們之間的關係。老師特別用 ★ 標出關係：只分析各部分、不看關係，就會失去系統觀。
  • 用證據重組讓分析可以被驗證：每個說法都要附上例子或數據（e.g.）。

How to judge the result如何判斷成果好不好

○Effective — matters MORE效能 Effective：比較重要

Goal / purpose reached — doing the right thing.達成目標／目的：做對的事。

>

✕Efficient — matters less效率 Efficient：次要

Output ↑ / Input ↓ — the ratio of output to input; doing things with the least resources.產出 ↑／投入 ↓：產出與投入的比值，用最少資源把事情做完。

Rule: effective first, then efficient.原則：先求有效能，再求有效率。

Common mistake常見誤區 inferred推論

Equating “fast” with “good”. A very efficient analysis that answers the wrong question (skipping ① Separate) is not effective.

把「快」當成「好」。一份很有效率、卻答錯題（跳過 ① 拆解）的分析，並不算有效能。

Logic chain邏輯鏈 inferred推論

  1. Treat the term project as a real product, not just an assignment.
  2. Write the PRD → every requirement must be verifiable.
  3. Build an MVP — minimum, but viable: it must create value the TA would pay for (WTP).
  4. Only something with WTP can be commercialized and transacted in a market.
  1. 把期末專題當成真正的產品，而不只是作業。
  2. 先寫 PRD：每個需求都必須可以驗證。
  3. 做出 MVP：功能最少，但要可行，也就是能創造目標受眾願意付錢的價值（WTP）。
  4. 有 WTP 的東西，才能在市場上商業化、被交易。

Key Take-aways & Glossary重點整理與名詞表

Key take-aways重點整理

  1. Analysis = ① Separate → ② Investigate → ③ Recombine with evidence.
  2. Separate into problem / demand / questions, then into Σ parts + Σ components + their relationships (relationships ★ important).
  3. Present results as a systematic, structured, process-oriented representation (Coggle mind map) → insights.
  4. Effective (reach the goal) matters more than efficient (output / input): effective first, then efficient.
  5. TP = a product (software / app — the BNA Agent, delivered as a webpage / SaaS).
  6. PRD → requirements → function verifications.
  7. MVP must create value (WTP) for the TA so it can be commercialized / transacted in the market (product ↔ consumers ↔ $).
  8. AI note-taking pipeline: recordings / images → notes → (ChatGPT, task agent) → analysis → summary → .md → document, or → .svg / SPA .html.
  9. Human value = critical thinking that creates content.
  1. 分析＝① 拆解 → ② 調查 → ③ 以證據重組。
  2. 先拆成問題／需求／提問，再細分成各部分＋各組成＋它們的關係（關係 ★ 最重要）。
  3. 用系統化、結構化、流程導向的方式呈現（Coggle 心智圖）→ 產生洞見。
  4. 效能（達成目標）比效率（產出／投入）重要：先求有效能，再求有效率。
  5. 期末專題＝一個產品（軟體／App：BNA Agent，以網頁／SaaS 形式提供）。
  6. PRD → 需求 → 功能驗證。
  7. MVP 必須為目標受眾（TA）創造價值（WTP），才能在市場上商業化、被交易（產品 ↔ 消費者 ↔ $）。
  8. AI 筆記流程：錄音／錄影／圖片 → 筆記 →（ChatGPT、Task agent）→ 分析 → 摘要 → .md → 文件，或 → .svg／SPA .html。
  9. 人的價值＝用批判性思考創造內容。
